Container Security Best Practices for Developers on OpenShift

This page gets you logged in to the OpenShift cluster, creates the workshop project, and exports the variables every later step uses. It is the only page that runs oc login. Do it before the session starts; it takes about ten minutes.

Prerequisites

Tool Version Why

oc

4.14+

Talk to the cluster. See the OpenShift Container Platform documentation

podman

4.9+

Build and run container images locally, no root daemon required

curl, envsubst

any recent

Call the app; fill ${VARIABLE} placeholders in manifests (envsubst is part of gettext)

git

any recent

Clone this repository

You do not need Go: the application is compiled inside the container build.

Verify your workstation:

oc version --client
podman --version
envsubst --version | head -1
The hands-on parts use a disposable workshop cluster. Step 3 submits a root deployment on purpose and Step 6 creates extra projects. Never run these steps on a production cluster.
On macOS and Windows, podman runs inside a small Linux VM. Start it once with podman machine start. Your machine is probably arm64, the cluster is amd64: Step 2 shows the one flag that handles that.

Log in to the Cluster

Two paths depending on how the workshop environment was prepared.

Option A: Full login (clusters provisioned for this workshop)

You receive the API endpoint and a token from the platform team. Log in, then give the context a stable name so later commands never hit the wrong cluster:

oc login --server=https://api.<cluster-domain>:443 --token=<token>
oc config rename-context "$(oc config current-context)" workshop
oc whoami --show-server --context workshop
The context is always called workshop, whatever the platform, so every command in the later steps can be pasted as written. Everything in this workshop works through the API, never through SSH to a node, which is exactly the developer surface you use in production.

Option B: Quick login (environment already prepared)

If your context is already configured, just verify it:

oc whoami --show-server --context workshop

Export Workshop Variables

What: Copy the variables template and load it into your shell.

Why: One file, sourced once per terminal, means no step page ever asks you to retype a name or an image reference.

git clone https://github.com/demon86rm/container-security-best-practices.git
cd container-security-best-practices
cp myenv.sh.example myenv.sh
# edit PROJECT if the cluster is shared, then:
source myenv.sh
echo $PROJECT

The images are built inside the cluster in Step 2 and stored in its internal registry. That avoids registry accounts, pull secrets and architecture mismatches during a short session.
Verify: The variables are set 
echo $PROJECT $DEMO_SECURE_IMAGE
sec-ws image-registry.openshift-image-registry.svc:5000/sec-ws/demo-secure:latest

Create the Workshop Project

~10 seconds

What: Create a dedicated project.

Why: It isolates the intentionally insecure demo resources from everything else, and reset is a single command.

oc new-project $PROJECT --context workshop
Verify: The project exists 
oc get project $PROJECT --context workshop
NAME     DISPLAY NAME   STATUS
sec-ws                  Active
